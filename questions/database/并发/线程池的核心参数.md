# 线程池的核心参数

## 联想记忆法

### 记忆口诀/联想

**口诀:"核最大队,队保活,工厂拒——七个参数:core、max、keepAlive、unit、queue、factory、handler"**

把线程池想成**一家奶茶店**:

- **corePoolSize**:店里**固定员工数**(常驻,没事也不裁)
- **maximumPoolSize**:**高峰期最多人手**(含临时工)
- **keepAliveTime + unit**:临时工**闲着多久就走**(非核心线程空闲超时回收)
- **workQueue**:门口**排队的单子队列**(人满了先排队)
- **threadFactory**:**招人渠道**(命名、是否守护线程)
- **handler**:**实在接不了的单子怎么办**(拒绝策略)

**口诀助记:"核心常驻、最大兜底、队列缓冲、超时回收、工厂命名、满了拒绝"——六个词串起全部参数。**

### 记忆原理

用"奶茶店"的日常运营把 7 个参数变成画面:固定员工、高峰加人、闲人辞退、排队、招人、拒单。记忆主线是**线程池的完整执行流程**:任务进来 → 核心线程跑 → 满了排队 → 队满了加临时工 → 人满了拒绝。只要背下这个流程,7 个参数自然浮现。再加一个金句:**无界队列会让 maxPoolSize 和拒绝策略形同虚设**。

### 关联知识

- **与阻塞队列关联**:四种队列的取舍(无界/有界/同步/延迟)直接决定线程池行为
- **与拒绝策略关联**:四种策略的适用场景(默认 AbortPolicy)
- **与 Executors 关联**:Executors 工厂方法就是这些参数的具体组合,可反推其隐患
- **与线程状态关联**:工作线程空闲时 workQueue.take() 进入 WAITING

## 深度解答

### 第一层:核心概念

#### 是什么

线程池的核心是 `ThreadPoolExecutor`,它接收 **7 个核心参数**:

```java
public ThreadPoolExecutor(
    int corePoolSize,        // 1. 核心线程数
    int maximumPoolSize,     // 2. 最大线程数
    long keepAliveTime,      // 3. 空闲存活时间
    TimeUnit unit,           // 4. 时间单位
    BlockingQueue<Runnable> workQueue,   // 5. 工作队列
    ThreadFactory threadFactory,         // 6. 线程工厂
    RejectedExecutionHandler handler     // 7. 拒绝策略
)
```

| 参数 | 含义 | 关键点 |
|---|---|---|
| corePoolSize | **核心线程数** | 常驻线程,默认空闲也不销毁 |
| maximumPoolSize | **最大线程数** | 线程上限 = 核心 + 临时 |
| keepAliveTime | 非核心线程**空闲存活时间** | 超过即回收(核心线程默认不回收) |
| unit | 时间单位 | 与 keepAliveTime 配合 |
| workQueue | **阻塞队列** | 核心线程满后任务排队 |
| threadFactory | 线程工厂 | 设置线程名、daemon、优先级 |
| handler | **拒绝策略** | 队列满 + 线程满时触发 |

### 第二层:底层原理

#### 执行流程(面试必背)

```
提交任务 → 判断
├─ 当前线程数 < corePoolSize        → 新建核心线程执行(即使有线程空闲,先加人)
├─ 当前线程数 ≥ corePoolSize        → 任务入队 workQueue
├─ 队列满 且 线程数 < maximumPoolSize → 新建非核心线程执行
└─ 队列满 且 线程数 = maximumPoolSize → 执行拒绝策略 handler
```

**注意细节**:任务提交后**先判断核心线程数再入队**,且核心线程数没满时即使有空闲线程也会新建线程——这是"**先加人,再排队,后招临时工,最后拒单**"的顺序。

#### 两个重要的"不一定"

1. **核心线程也可能被回收**:`allowCoreThreadTimeOut(true)` 后,核心线程空闲超时也会销毁
2. **线程数不是一直不变**:池通过 `ctl`(int 高 3 位存状态、低 29 位存线程数)原子管理线程数,防止并发下重复创建

#### 队列类型(决定池的行为)

| 队列 | 特性 | 后果 |
|---|---|---|
| LinkedBlockingQueue | 默认**无界** | 队列永不"满",maxPoolSize 与拒绝策略**失效** |
| ArrayBlockingQueue | **有界**,需指定容量 | 可控,配合拒绝策略使用 |
| SynchronousQueue | 无缓冲,直接交接 | 有任务就立刻找线程,适合 CachedThreadPool |
| DelayedWorkQueue | 延迟队列 | ScheduledThreadPool 专用 |

#### 拒绝策略(handler 四种)

| 策略 | 行为 |
|---|---|
| AbortPolicy(默认) | **抛 RejectedExecutionException**(最安全,明确失败) |
| CallerRunsPolicy | 由**提交任务的线程**自己执行(降速不丢任务) |
| DiscardPolicy | **静默丢弃**(最危险,丢任务无感知) |
| DiscardOldestPolicy | 丢弃队列**最老**的任务,再重试提交 |

#### 线程池生命周期

RUNNING → SHUTDOWN(不再接新任务,处理完存量)→ STOP(中断)→ TIDYING → TERMINATED。拒绝策略只在 RUNNING/SHUTDOWN 之外的非法提交时兜底。

### 第三层:实践应用

```java
// 生产推荐:手动创建,有界队列 + 自定义工厂 + 明确拒绝策略
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    4,                          // core = 4
    8,                          // max = 8
    60, TimeUnit.SECONDS,       // 非核心空闲 60s 回收
    new ArrayBlockingQueue<>(100),   // 有界队列,防 OOM
    new ThreadFactory() {        // 自定义线程名,便于排查
        private final AtomicInteger n = new AtomicInteger();
        @Override public Thread newThread(Runnable r) {
            return new Thread(r, "biz-pool-" + n.incrementAndGet());
        }
    },
    new ThreadPoolExecutor.CallerRunsPolicy()  // 提交线程兜底执行
);
```

- **参数设置原则**:core 依据业务常流量、max 依据峰值、队列容量依据"允许的积压量"
- **监控**:`pool.getTaskCount()/getCompletedTaskCount()/getActiveCount()`,线程名规范化是排查利器
- **关闭**:`shutdown()`(等存量任务完成)vs `shutdownNow()`(interrupt 全部)

### 第四层:深入思考

**追问 1:corePoolSize 和 maximumPoolSize 为什么分开?**
应对流量波动:平时保持 core 规模省资源,高峰临时扩到 max,闲下来 keepAliveTime 回收临时线程——弹性伸缩,避免线程数永远维持峰值。

**追问 2:无界队列有什么隐患?**
LinkedBlockingQueue 永不拒绝,任务无限积压 → **内存 OOM**;且线程数最多到 core,大流量下全部排队,响应越来越慢。

**追问 3:为什么 prestartCoreThread 有用?**
默认池懒启动(首个任务才建核心线程);`prestartAllCoreThreads()` 可预热,避免高并发第一波任务都撞上"建线程"开销。

### 答题逻辑框架

1. **抛结论**:7 个参数,先列名字
2. **背执行流程**:核心不够→加人;核心满→排队;队满→加临时工;全满→拒绝
3. **逐个讲参数细节**:keepAliveTime 只管非核心、队列选型决定生死、拒绝策略四种
4. **给实践**:手写 ThreadPoolExecutor 示例,强调有界队列 + 命名工厂
5. **埋延伸**:引出 Executors 陷阱、线程池大小设定

### 重点得分点

- ✅ 7 个参数名称完整、顺序正确
- ✅ 执行流程四步(先加人再排队,不是先排队)
- ✅ 队列类型与后果(无界队列让 max 失效)
- ✅ 四种拒绝策略 + 默认 AbortPolicy

### 常见误区

- ❌ "任务来了先入队,队满了再判断核心线程"——顺序反了:先看核心线程数
- ❌ "keepAliveTime 管所有线程"——只管非核心(除非 allowCoreThreadTimeOut)
- ❌ "Executors.newFixedThreadPool 没有问题"——无界队列是 OOM 隐患
- ❌ "线程池满了就抛异常"——只有 AbortPolicy 抛,其他策略不抛
