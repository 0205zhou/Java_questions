# 创建线程的方式

## 联想记忆法

### 记忆口诀/联想

**口诀:"四种写法一条路:继承、实现、带返回值、丢池子——本质都是 Runnable"**

把创建线程想成**四种叫外卖方式**:

1. **继承 Thread**:自己开店(重写 run),单继承限制——开了这家店就不能再开别的店(不能继承其他类)
2. **实现 Runnable**:给跑腿小哥派活(任务与执行者分离),可以同时打多份工(实现多个接口)
3. **实现 Callable**:跑腿小哥**要带回执**(返回值 + 抛异常),用 FutureTask 接收
4. **线程池**:点外卖平台(ExecutorService),小哥复用不新招(线程复用),最优雅

**本质:不管哪种写法,最终都是把 Runnable 交给 Thread 去跑;唯一的"创建线程"动作是 start()。**

### 记忆原理

用"四种叫外卖"的场景把四种写法挂上钩,核心锚点是"**任务与线程分离**"这个设计思想:除了直接继承 Thread,其余三种都是"把任务(Runnable/Callable)提交给执行者(Thread/Executor)"。记住最后一句金句:**new Thread() 只是创建对象,start() 才创建线程**,这是面试最爱挖的细节。

### 关联知识

- **与线程状态关联**:start() 后进入 RUNNABLE,直接调 run() 不会变状态
- **与线程池关联**:ExecutorService.submit(Callable) 返回 Future,是 Callable 的典型消费方式
- **与 Java 21 关联**:虚拟线程 Thread.ofVirtual(),是"创建线程"的最新答案
- **与 Callable/Future 关联**:返回值获取、超时控制、取消任务

## 深度解答

### 第一层:核心概念

#### 是什么

创建线程有四种经典方式,本质都是**把 Runnable(或 Callable)交给 Thread 执行**:

```java
// 方式一:继承 Thread(不推荐,单继承限制 + 任务与线程耦合)
class MyThread extends Thread {
    @Override public void run() { System.out.println("继承 Thread"); }
}
new MyThread().start();

// 方式二:实现 Runnable(推荐:任务与执行者分离,可结合 Lambda)
Runnable task = () -> System.out.println("实现 Runnable");
new Thread(task).start();

// 方式三:Callable + FutureTask(有返回值、可抛异常)
Callable<Integer> callable = () -> { Thread.sleep(100); return 42; };
FutureTask<Integer> futureTask = new FutureTask<>(callable);
new Thread(futureTask).start();
Integer result = futureTask.get();     // 阻塞获取返回值

// 方式四:线程池(生产首选:复用线程、控制并发)
ExecutorService pool = Executors.newFixedThreadPool(2);
Future<Integer> future = pool.submit(callable);
Integer result2 = future.get();
pool.shutdown();
```

### 第二层:底层原理

#### 唯一入口:start()

`new Thread()` 只创建**线程对象**(状态 NEW),真正创建 OS 线程的是 `start()`:

```java
public synchronized void start() {
    // ... 状态校验
    start0();   // native 方法,创建 OS 线程并回调 run()
}
```

- `start0()` 是 native 方法,由 JVM 调用操作系统接口创建线程,线程进入 **RUNNABLE**
- **start() 只能调一次**,重复调用抛 IllegalThreadStateException
- **直接调 run() 不是创建线程**,只是普通方法调用,在执行线程上跑,状态不变
- **注意**:线程的执行代码是 run(),但线程的启动必须走 start()

#### 四种方式的关系

```
        ┌─────────────┐    适配      ┌──────────────┐
Callable│call(): 返回值│ ──────────► │ Runnable.run │
        └─────────────┘  FutureTask │ (无返回值)    │
                                    └──────┬───────┘
        ┌─────────────┐                   │ 交给
 Runnable│run(): 无返回值│ ◄────────────────┘
        └─────────────┘        Thread.start()
```

- **Runnable vs Callable**:Callable.call() **有返回值且可抛受检异常**;Runnable.run() 无返回值、不能抛受检异常。FutureTask 实现了 Runnable,把 Callable 适配成可提交任务
- **Future.get()**:阻塞等待结果;可设超时 `get(timeout, unit)`;`future.cancel()` 可取消任务(interrupt 线程)
- **为什么推荐 Runnable 而非继承 Thread**:Java 单继承,继承 Thread 后无法继承其他类;实现 Runnable 让**任务与线程解耦**,同一个任务可交给不同线程/线程池执行;组合优于继承

#### 虚拟线程(Java 21+)

JDK 21 正式提供**虚拟线程(virtual thread)**,创建方式:

```java
Thread vt = Thread.ofVirtual().name("vt-1").start(task);
Thread vt2 = Thread.startVirtualThread(task);   // 便捷方法
```

- 虚拟线程是 JVM 管理的轻量级线程,**几百万个都不成问题**,IO 密集场景性能远超平台线程
- 底层仍是 Runnable 思想:`Thread.ofVirtual()` 返回 builder,start 后调度到平台线程(载体线程)上执行

### 第三层:实践应用

```java
// 生产代码原则:禁止裸 new Thread(),一律走线程池
ExecutorService pool = Executors.newFixedThreadPool(4);
try {
    List<Future<Integer>> futures = new ArrayList<>();
    for (int i = 0; i < 10; i++) {
        futures.add(pool.submit(() -> heavyTask()));
    }
    for (Future<Integer> f : futures) {
        f.get(3, TimeUnit.SECONDS);      // 带超时,防止永久阻塞
    }
} finally {
    pool.shutdown();                     // 优雅关闭,不主动中断运行中的任务
}
```

- **选型**:无返回值 → Runnable;有返回值 → Callable + Future;需要定时/周期 → ScheduledExecutorService;高并发 IO → 虚拟线程
- **多任务并行等待**:用 `CompletableFuture` 组合(anyOf/allOf),比逐个 get 更优雅
- **关闭**:池用完必须 shutdown/shutdownNow,否则非守护线程阻止 JVM 退出

### 第四层:深入思考

**追问 1:线程到底是怎么创建出来的?**
start() → start0()(native)→ JVM 调用 pthread_create / CreateThread 等 OS API → OS 分配内核栈、TCB 并调度 → 回调 Java run()。这也是为什么说"Java 线程是 OS 线程的一比一包装"。

**追问 2:为什么阿里规约禁止手动 new Thread?**
裸线程无法复用(每次创建/销毁开销大)、无法限制并发数(线程数失控 → OOM)、缺少统一管理(命名、监控、优雅关闭)。线程池天然解决这三点。

**追问 3:Runnable 和 Callable 如何互相转换?**
`Executors.callable(runnable)` 把 Runnable 转 Callable(返回 null);`FutureTask` 把 Callable 适配为 Runnable。Java 8 的 lambda:`() -> { return value; }` 直接是 Callable,`() -> {}` 是 Runnable。
