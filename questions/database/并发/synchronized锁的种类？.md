# synchronized锁的种类？

### 1. 🧠 联想记忆法

**记忆口诀/联想**：先偏向，再轻量，后重量；对象锁管实例，类锁管全类。

**记忆原理**：`synchronized` 的“锁的种类”通常有两种问法：一种是从代码写法看，分实例锁、对象锁、类锁；另一种是从 JVM 状态看，分偏向锁、轻量级锁、重量级锁。答题时把这两套口径先讲清楚，就不会答偏。

**关联知识**：这题常和对象头（Mark Word）、锁升级、自旋、`BLOCKED` 状态、`Lock` 的对比一起考。面试官想听的不是你背了几个名词，而是你知不知道 JVM 为什么要升级锁、什么时候会膨胀。

### 2. 📖 深度解答

#### 2.1 核心概念：`synchronized` 的锁既有“加在哪儿”，也有“处于什么状态”

` synchronized` 的锁种类，最好分成两层来讲：

1. **按加锁位置分**：实例锁、类锁、代码块锁
2. **按 JVM 锁状态分**：偏向锁、轻量级锁、重量级锁

这两套分类不是互相冲突，而是从不同维度观察同一个东西。

---

#### 2.2 第一层：按加锁位置分类

##### 1）实例锁

```java
public synchronized void foo() {
    // 锁的是 this
}

public void bar() {
    synchronized (this) {
        // 锁的是当前对象
    }
}
```

实例锁保护的是某个对象实例的共享状态。同一个对象上的多个同步方法互斥，不同对象实例之间通常互不影响。

##### 2）类锁

```java
public static synchronized void baz() {
    // 锁的是 Demo.class
}

public void qux() {
    synchronized (Demo.class) {
        // 锁的是类对象
    }
}
```

类锁保护的是类级别共享资源。因为 `Class` 对象在 JVM 中通常只有一份，所以所有实例共享同一把类锁。

##### 3）同步代码块锁

同步代码块最灵活，锁对象由你自己指定：

```java
private final Object lock = new Object();

public void incr() {
    synchronized (lock) {
        count++;
    }
}
```

这也是工程里更推荐的写法之一，因为它可以把锁粒度缩到最小，并避免直接锁 `this` 或 `Class` 带来的外部干扰。

---

#### 2.3 第二层：按 JVM 锁状态分类

##### 1）偏向锁

偏向锁的思想是：如果一个锁总是被同一个线程反复获取，那就没必要每次都做重型同步。

它会把锁“偏向”第一次获得它的线程，后续同线程进入时开销很小。

##### 2）轻量级锁

当出现其他线程竞争时，偏向锁会撤销，升级成轻量级锁。轻量级锁通常通过 CAS 和自旋来争抢锁，尽量避免线程挂起和切换。

##### 3）重量级锁

如果竞争继续加剧，自旋再也不划算，锁就会膨胀成重量级锁。此时线程可能进入阻塞和唤醒流程，开销更大。

这三个状态可以粗略记成：

```text
无竞争/低竞争 → 偏向锁
轻度竞争 → 轻量级锁
高竞争 → 重量级锁
```

---

#### 2.4 底层原理：为什么会有锁升级

JVM 之所以设计锁升级，是因为真实业务里大多数锁都不是一直高竞争。

- 没竞争时，用重量级锁太浪费
- 轻竞争时，直接挂起线程也太重
- 高竞争时，CAS 自旋又会空转浪费 CPU

所以 JVM 选择按竞争程度逐步升级，尽量让“常见情况更快，极端情况也能兜住”。

对象头里的 Mark Word 会记录锁状态，JVM 根据状态切换来完成升级、撤销和膨胀。

---

#### 2.5 实践应用：怎么理解这几种锁

```java
public class Counter {
    private int num;
    private static int total;
    private final Object lock = new Object();

    public synchronized void add() {
        num++;
    }

    public void add2() {
        synchronized (lock) {
            num++;
        }
    }

    public static synchronized void addTotal() {
        total++;
    }
}
```

这段代码里：

- `add()` 锁的是当前对象
- `add2()` 锁的是私有对象 `lock`
- `addTotal()` 锁的是 `Counter.class`

实践上通常建议：

- 保护实例变量，用实例锁
- 保护静态共享变量，用类锁
- 业务代码优先锁私有对象，别轻易锁 `this`

---

#### 2.6 深入思考：为什么不只讲一种分类

如果只讲“偏向锁、轻量级锁、重量级锁”，容易忽略代码层面的锁对象。

如果只讲“实例锁、类锁”，又会漏掉 JVM 的优化状态。

所以最完整的答法是：

- **先说加锁位置**：实例锁、类锁、代码块锁
- **再说 JVM 状态**：偏向锁、轻量级锁、重量级锁
- **最后补一句**：锁升级是 JVM 为了适应不同竞争强度做的优化

这样回答，层次最稳。

3. 再讲 JVM 层面：偏向锁、轻量级锁、重量级锁

#### 3.2 重点得分点

- 明确区分实例锁和类锁
- 能说出偏向锁、轻量级锁、重量级锁
- 知道静态同步方法锁的是 `Class` 对象
- 知道锁升级是为了适配不同竞争场景

#### 3.3 常见误区

- 把对象锁和类锁混为一谈
- 以为 `synchronized` 只有一种状态
- 只会背名词，不会说升级过程
- 锁公共对象，导致外部代码也能参与竞争

#### 3.4 可直接复述的收尾话术

你可以最后总结一句：

> `synchronized` 的锁种类可以从代码层面看成实例锁和类锁，也可以从 JVM 运行状态看成偏向锁、轻量级锁和重量级锁。前者回答“锁在哪里”，后者回答“锁现在是什么状态”，两套口径一起讲最完整。
