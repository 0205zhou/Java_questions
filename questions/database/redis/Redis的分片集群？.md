# Redis的分片集群？

## 联想记忆法

### 记忆口诀/联想

**口诀：一分槽，二成组，三主三从，四靠客户端找路。**

- **一分槽**：Redis Cluster 把数据切成 16384 个 hash slot。
- **二成组**：每个主节点负责一部分槽位，下面挂从节点。
- **三主三从**：常见生产形态是多主多从，既分担写压力也保证高可用。
- **四靠客户端找路**：客户端先连任意节点，再根据 `MOVED` / `ASK` 跳转到正确节点。

### 记忆原理

把“分片集群”记成“**先切槽，再分片，再容灾，再迁移**”最容易串起来。面试时只要先说清它是**分布式分片 + 高可用**的组合，就不会把它和哨兵模式混淆。

### 关联知识

- 会关联到 **哨兵**：哨兵只做高可用，不做分片。
- 会关联到 **hash slot**：Redis Cluster 按槽分配 key。
- 会关联到 **MOVED / ASK**：客户端重定向机制。
- 会关联到 **hash tag**：让多个 key 落到同一槽位。

## 深度解答

### 1. 核心概念：Redis Cluster 既分片，又高可用

Redis Cluster 通常就是面试里说的“Redis 分片集群”。它把整个 key 空间切成 `16384` 个槽位，不同主节点负责不同槽位，于是数据和写流量可以横向分散。

它和哨兵最大的区别是：

- **哨兵**：主从复制 + 自动故障转移
- **Cluster**：主从复制 + 自动故障转移 + 数据分片

所以 Cluster 解决的是“**单机容量不够、写压力太大**”的问题，而不只是“主挂了怎么办”。

### 2. 底层原理：hash slot 怎么分

Redis Cluster 不是按 key 的字面值直接均分，而是先对 key 做 CRC16，再对 `16384` 取模：

```text
slot = CRC16(key) % 16384
```

每个 slot 归属于某个 master。客户端写入某个 key 时，会先算 slot，再去对应 master 执行。  
如果连错节点，Redis 会返回重定向：

- `MOVED`：这个槽现在在别的节点，去新地址
- `ASK`：迁槽过程中临时跳转一次

### 3. 集群内部是怎么运转的

Cluster 里每个节点都保存全量的槽位映射信息，并通过集群总线交换状态。节点之间会互相感知对方是否在线、是否失联、是否需要切主。

典型结构可以理解成：

```text
Master1 <- Slave1
Master2 <- Slave2
Master3 <- Slave3
```

每个 master 管一部分槽位，master 挂了以后，自己的从节点可以提升为新的 master，整个槽位归属关系再同步给集群。

### 4. 实践应用：怎么搭和怎么用

常见创建方式：

```bash
redis-cli --cluster create \
  127.0.0.1:7001 127.0.0.1:7002 127.0.0.1:7003 \
  127.0.0.1:7004 127.0.0.1:7005 127.0.0.1:7006 \
  --cluster-replicas 1
```

常见排查命令：

```bash
CLUSTER INFO
CLUSTER NODES
CLUSTER KEYSLOT user:1
```

如果要让多个 key 落到同一个槽位，可以用 **hash tag**：

```redis
user:{1001}:name
user:{1001}:age
```

花括号里的内容相同，这两个 key 就会被路由到同一槽，方便事务、Lua 脚本或多 key 操作。

### 5. 深入思考：Cluster 的代价

Cluster 不是“免费午餐”：

- 多 key 操作会受跨槽限制
- 迁槽、扩容、缩容都比单机复杂
- 客户端必须支持 Cluster 协议
- 业务上最好尽量按业务维度设计 key，减少跨槽访问

所以它更适合：

- 数据量明显超过单机容量
- 写流量比较大
- 可接受一定的运维复杂度

不适合：

- 只是想要高可用但数据量不大
- 业务经常依赖大量跨 key 原子操作

## 回答思路

### 答题逻辑框架

1. 先说 Redis Cluster 是“分片 + 高可用”。
2. 再说它按 `16384` 个 hash slot 分配数据。
3. 然后讲 `MOVED` / `ASK` 和客户端路由。
4. 最后补充 hash tag、扩容迁槽和与哨兵的区别。

### 重点得分点

- 能说出 `16384` 个 slot。
- 能解释 `MOVED` 和 `ASK`。
- 能区分 Cluster 和 Sentinel。
- 能说明 hash tag 的用途。

### 常见误区

- 误区 1：Cluster 就是多台 Redis 简单复制。  
  正解：它是分片架构，不是纯复制。

- 误区 2：Cluster 可以随便做多 key 操作。  
  正解：跨槽多 key 会受限制。

- 误区 3：Cluster 只解决容量，不解决高可用。  
  正解：Cluster 也支持主从切换。

### 面试话术

“Redis 分片集群一般指 Redis Cluster，它把 key 空间切成 16384 个 hash slot，由多个 master 分担不同槽位，每个 master 再配从节点做高可用。客户端先按 CRC16 算槽，再通过 `MOVED`、`ASK` 完成路由和重定向。它既解决了单机容量和写压力问题，也保留了故障自动切换能力，但跨槽多 key 操作会受限制。”
