# Spring里的AOP是什么

## 联想记忆法

### 记忆口诀/联想

**口诀：核心代码管主线，横切逻辑放切面；代理负责织入，切点决定哪里增强。**

可以把 AOP 想成给一条业务流水线安装“公共检查站”：订单创建是主流程，日志、权限、事务、监控是很多流程都需要经过的检查站。业务代码不需要在每个方法里重复写这些逻辑，Spring 在方法调用边界通过代理统一加入。

### 记忆原理

AOP 的四个关键词可以串成一条线：**关注点、切面、切点、通知**。

- **横切关注点**：日志、事务、权限等会横跨多个业务模块的公共逻辑。
- **切面（Aspect）**：横切逻辑的组织单元。
- **切点（Pointcut）**：规定哪些方法需要被增强。
- **通知（Advice）**：规定在目标方法前、后或异常时执行什么代码。

### 关联知识

- AOP 依赖 IoC 容器管理 Bean，常通过 `BeanPostProcessor` 创建代理。
- Spring AOP 主要使用 JDK 动态代理和 CGLIB 代理，不等同于 AspectJ 的编译期或类加载期织入。
- `@Transactional`、`@Cacheable`、`@Async` 等功能都能体现 AOP 的代理增强思想。

## 深度解答

### 第一层：核心概念

AOP（Aspect-Oriented Programming，面向切面编程）是一种**将横切关注点从核心业务逻辑中分离出来，并在指定执行点统一织入的编程思想**。

面向对象擅长把系统拆成用户、订单、商品等业务对象；但日志、权限、事务、链路追踪等逻辑通常会同时出现在很多对象和方法中。如果把它们直接写进每个业务方法，就会产生重复代码、业务代码变脏、修改困难等问题。AOP 的目标不是替代面向对象，而是补充面向对象难以处理的“跨多个模块的公共行为”。

例如，下面的业务方法只表达订单创建：

```java
public Order createOrder(CreateOrderCommand command) {
    return orderRepository.save(buildOrder(command));
}
```

事务、日志和耗时统计可以通过切面统一加入，而不必在每个业务方法里手动调用。

### 第二层：核心术语与工作原理

| 术语 | 含义 |
|---|---|
| Join Point（连接点） | 程序执行过程中可以被增强的位置，Spring AOP 中通常指方法执行 |
| Pointcut（切点） | 对连接点进行筛选的表达式，例如某个包下的所有方法 |
| Advice（通知） | 在目标方法前后执行的增强逻辑 |
| Aspect（切面） | 切点和通知的组合，表示一类横切功能 |
| Target（目标对象） | 被增强的原始业务对象 |
| Proxy（代理对象） | 对外暴露的增强对象，负责拦截调用并执行通知 |
| Weaving（织入） | 把切面逻辑应用到目标对象的过程 |

Spring AOP 的典型调用链如下：

```text
客户端获取 Bean
      ↓
Spring 返回代理对象，而不是直接返回原始对象
      ↓
调用代理方法
      ↓
匹配切点并执行前置通知
      ↓
调用目标方法
      ↓
执行返回通知、异常通知或环绕通知
      ↓
返回结果
```

Spring 创建 Bean 时，会通过自动代理创建器等 `BeanPostProcessor` 判断当前 Bean 是否匹配某个切面。如果匹配，就把一个或多个拦截器包装成代理对象。调用代理方法时，拦截器链负责依次执行通知，最后再调用目标对象的方法。

### 第三层：Spring AOP 的常见写法

```java
@Aspect
@Component
public class OperationLogAspect {

    @Around("execution(* com.example.order.service..*(..))")
    public Object log(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return joinPoint.proceed();
        } finally {
            long cost = System.currentTimeMillis() - start;
            System.out.println(joinPoint.getSignature() + " cost=" + cost + "ms");
        }
    }
}
```

通知类型通常包括：

- `@Before`：目标方法执行前执行，例如参数检查、权限校验。
- `@After`：目标方法结束后执行，无论成功还是异常都会执行。
- `@AfterReturning`：目标方法正常返回后执行，可以读取返回值。
- `@AfterThrowing`：目标方法抛出异常后执行，例如记录异常信息。
- `@Around`：环绕目标方法执行，能决定是否调用目标方法，也能修改参数和返回值，最灵活但应谨慎使用。

### 第四层：代理方式与限制

当目标类实现了接口时，Spring 可以使用 JDK 动态代理，代理对象实现同样的接口；当没有接口或配置要求使用类代理时，可以使用 CGLIB，通过生成目标类的子类进行代理。

因此 Spring AOP 有几个重要限制：

1. **自调用可能失效**：类内部使用 `this.otherMethod()` 调用时，没有经过代理对象，切面通常不会执行。常见解决方式是拆分 Bean、从容器获取代理，或调整调用结构。
2. **`private` 方法无法被正常代理增强**：外部代理无法拦截私有方法。
3. **`final` 类或 `final` 方法限制 CGLIB 继承和覆写**，通常不能按预期增强。
4. **代理对象与目标对象不是同一个对象**：排查事务、缓存、权限问题时，要确认调用是否经过 Spring 容器拿到的代理。
5. Spring AOP 默认主要针对 Spring Bean 的方法执行，不能像 AspectJ 那样天然覆盖任意对象的所有连接点。

### 第五层：深入思考

AOP 的价值在于统一处理稳定、通用、与业务主线相对独立的逻辑，但不是所有代码都适合放进切面。切面过多会让调用链变得隐蔽，业务行为难以从一个类中直接看全；切点写得过宽还可能误增强不该增强的方法。因此切面应保持职责单一，切点尽量明确，并配合日志、链路追踪和测试验证实际执行顺序。

还要区分 AOP 与过滤器、拦截器：Filter 更靠近 Servlet 请求入口，Interceptor 主要围绕 Spring MVC 的请求处理流程，AOP 更关注 Bean 方法调用。三者可以配合使用，但拦截粒度和生命周期不同。

4. 说明 Spring AOP 基于动态代理，补充 JDK 代理和 CGLIB 的区别。
5. 最后说自调用、`private`、`final` 等限制，体现对实际运行机制的理解。

### 重点得分点

- 说明 AOP 处理的是横切关注点，而不是简单的代码复用。
- 能讲清“代理拦截 → 通知 → 目标方法”的调用链。
- 能举出事务、日志、权限、缓存、监控等实际场景。
- 明确 Spring AOP 主要基于动态代理，并知道自调用可能导致增强失效。

### 常见误区

- 把 AOP 说成一种具体的代理 API；AOP 首先是一种编程思想。
- 认为切面会修改原始业务类源码；Spring 通常是通过代理对象完成增强。
- 认为加了 `@Transactional` 就一定生效；调用必须经过代理，事务配置也必须正确。
- 把拦截器和 AOP 当成同一个东西；两者的拦截层次不同。

### 面试话术

“AOP 是面向切面编程，主要解决日志、事务、权限、缓存这类横切关注点重复散落的问题。Spring AOP 通常基于 JDK 动态代理或 CGLIB，在 Bean 创建后生成代理对象，外部调用代理方法时根据切点匹配通知，再调用目标方法。使用时要注意自调用、private 和 final 方法等场景可能无法被代理增强。”
