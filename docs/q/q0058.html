过滤器和拦截器的区别

Filter Interceptor Spring MVC

过滤器和拦截器的区别

🧠 联想记忆法

记忆口诀/联想

口诀：过滤器守城门，拦截器盯业务。

  • 过滤器（Filter）：站在 Web 容器（Web Container）门口，谁进谁出都先过一遍
  • 拦截器（Interceptor）：站在 Spring MVC 业务入口，专门拦 Controller（控制器）执行过程

记忆原理

这题最容易记错的是“谁先执行、作用范围在哪、依赖哪个体系”。把过滤器理解成“Servlet 规范层面的门卫”，把拦截器理解成“Spring MVC 调度链里的业务哨兵”，就能自然区分作用时机、可拿到的上下文、适用场景等差异。

关联知识

  • 与 Servlet 规范 关联
  • 与 DispatcherServlet 关联
  • 与 Spring MVC 执行流程 关联
  • 与 AOP、统一鉴权、日志追踪 关联

📖 深度解答

核心概念

过滤器和拦截器本质上都是“在目标逻辑执行前后做增强”的机制，但它们分属不同层次：

  • 过滤器（Filter）：属于 Servlet 规范，是 Web 容器提供的机制
  • 拦截器（Interceptor）：属于 Spring MVC，是 Spring 框架提供的机制

底层原理

1. 所属层次不同

过滤器运行在 Servlet 容器层，在请求进入 DispatcherServlet 之前就能生效。

拦截器运行在 Spring MVC 层，是在 DispatcherServlet 找到 Handler（处理器）之后、Controller 执行前后生效。

2. 作用范围不同

  • 过滤器可以拦所有进入 Web 容器的请求，包括静态资源
  • 拦截器主要拦 Spring MVC 管理的请求，一般针对 Controller 方法

3. 可获取上下文不同

过滤器拿到的是原始 ServletRequest、ServletResponse，更底层。

拦截器可以拿到 Handler，知道当前要执行哪个 Controller、哪个方法，所以更适合做业务相关增强。

4. 生命周期与依赖不同

过滤器依赖 Servlet 容器管理。

拦截器由 Spring 容器管理，可以很方便地注入 Spring Bean。

适用场景

过滤器适合：
- 字符编码处理
- 跨域（CORS，Cross-Origin Resource Sharing）
- XSS（Cross Site Scripting，跨站脚本）过滤
- 请求日志粗粒度记录

拦截器适合：
- 登录校验
- 权限校验
- 接口耗时统计
- 用户身份上下文注入
- 业务级审计日志

代码示例

// Filter 示例
@WebFilter(urlPatterns = "/*")
public class TraceFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        long start = System.currentTimeMillis();
        chain.doFilter(request, response);
        System.out.println("filter cost=" + (System.currentTimeMillis() - start));
    }
}

// Interceptor 示例
@Component
public class LoginInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        return request.getHeader("token") != null;
    }
}

深入思考

  1. 过滤器更通用、更底层，拦截器更贴近 Spring MVC 业务语义。
  2. 如果要拦静态资源或做容器级处理，用过滤器更合适。
  3. 如果要做基于 Controller 方法的鉴权、审计、埋点，用拦截器更合适。
  4. 面试进阶点：还能补充 AOP（Aspect-Oriented Programming，面向切面编程） 与拦截器的区别——AOP 面向方法调用，拦截器面向 Web 请求流程。

🗺️ 回答思路

  1. 先给结论：过滤器属于 Servlet，拦截器属于 Spring MVC。
  2. 再从“执行时机、作用范围、获取上下文、依赖管理、适用场景”五个维度展开。
  3. 最后补一句：
  4. 容器级通用处理用 Filter
  5. 业务请求增强用 Interceptor
  6. 如果追问，就展开执行顺序和与 AOP 的区别。
