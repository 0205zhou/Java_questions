XXL-Job在项目中的使用步骤？

XXL-Job在项目中的使用步骤？

联想记忆法

记忆口诀/联想

口诀：先装调度中心，再配执行器，最后建任务、挂处理器、设路由。

把 XXL-Job 想成“总部 + 分部 + 员工”：

  • 总部：xxl-job-admin，负责页面、调度、日志、路由。
  • 分部：执行器应用，负责真正执行任务。
  • 员工：@XxlJob 标记的方法，就是具体任务处理器。

记忆原理

XXL-Job 的使用路径非常稳定：先把平台搭起来，再让业务服务接入，最后在后台创建任务并触发执行。只要记住“Admin 管任务、Executor 跑任务、JobHandler 写业务”，其余步骤基本都能顺着推出。

关联知识

  • XXL-Job 是分布式任务调度平台，不是普通 @Scheduled 定时器。
  • 调度中心和执行器通过 HTTP 交互。
  • 任务支持路由、阻塞、超时、重试和告警。

深度解答

第一层：核心概念

XXL-Job 在项目中的使用，通常分为两部分：

  • xxl-job-admin：调度中心，负责管理任务和触发调度
  • xxl-job-executor：执行器，负责执行具体任务逻辑

它解决的是“谁来调度、谁来执行、怎么观察结果”的问题。

第二层：标准使用步骤

1. 部署调度中心

先启动 xxl-job-admin，并配置数据库、账号密码等基础信息。调度中心提供 Web 控制台，用来创建、编辑、启停和查看任务。

2. 引入执行器依赖

在业务项目中引入执行器依赖，让这个 Spring Boot 服务具备接收调度请求的能力。

3. 配置执行器参数

常见配置包括：

  • xxl.job.admin.addresses
  • xxl.job.executor.appname
  • xxl.job.executor.accessToken
  • xxl.job.executor.port
  • xxl.job.executor.logpath

这些配置决定执行器连接哪个调度中心、对外暴露什么名字、用什么端口接收调度、日志写到哪里。

4. 编写 JobHandler

在业务代码中写任务处理器：

@XxlJob("demoJobHandler")
public void demoJobHandler() {
    // 执行业务逻辑
}

这个 handler 是执行器真正执行的入口。调度中心配置的 handler 名称要和注解值一致。

5. 启动执行器并注册

执行器启动后，会向调度中心注册自己。调度中心可以发现在线执行器，并在后台页面中绑定它。

6. 在后台创建任务

在 xxl-job-admin 控制台中新建任务，通常要配置：

  • 任务名称
  • Cron 表达式
  • 执行器 AppName
  • JobHandler 名称
  • 任务参数
  • 路由策略
  • 阻塞策略
  • 失败重试
  • 超时设置

7. 触发执行并查看日志

到达调度时间后，调度中心会调用执行器提供的接口触发任务执行。任务执行完后，执行器回传结果，调度中心和控制台可查看日志和失败信息。

第三层：完整链路

Admin 创建任务
  -> Executor 注册
  -> 调度中心扫描任务
  -> 根据 Cron 触发
  -> 按路由策略选择执行器
  -> 调用执行器
  -> 找到 @XxlJob 对应方法
  -> 执行业务逻辑
  -> 回调执行结果
  -> 控制台查看日志

第四层：关键配置和策略

1. 路由策略

当有多个执行器实例时，可以选择：

  • 轮询
  • 随机
  • 故障转移
  • 忙碌转移
  • 一致性哈希

2. 阻塞策略

当任务触发太频繁，前一个任务还没结束时，可以选择：

  • 单机串行
  • 丢弃后续调度
  • 覆盖之前调度

3. 失败重试

任务失败后可以按次数重试，但不要无限重试，避免放大故障。

4. 日志与告警

上线后一定要配置日志路径和监控告警，否则任务失败只能“黑盒排查”。

第五层：实践建议

  • 任务逻辑尽量幂等。
  • 长任务要考虑超时和阻塞策略。
  • 不要把任务逻辑写在 Controller 里。
  • 生产环境建议统一通过 admin 管理任务，不要在代码里硬编码调度。

回答思路

答题逻辑框架

  1. 先区分 Admin 和 Executor。
  2. 再按部署、配置、注册、编写 handler、后台建任务来讲步骤。
  3. 补充路由、阻塞、重试和日志。

重点得分点

  • 能说出调度中心和执行器的职责。
  • 能说出执行器配置项。
  • 能说出 @XxlJob 是任务入口。
  • 能说出后台创建任务后由调度中心触发执行。

常见误区

  • 认为 XXL-Job 只是普通定时器。
  • 认为只写 @XxlJob 就能跑，不需要 admin。
  • 不知道任务要在控制台里配置 Cron 和 handler。

面试话术

“XXL-Job 的使用步骤一般是先部署 xxl-job-admin 调度中心，再在业务服务中接入执行器依赖并配置 admin 地址、appname、token 和端口，然后用 @XxlJob 编写 handler，在控制台中创建任务并设置 Cron、路由和阻塞策略。调度中心到点后触发执行器执行，任务结果和日志都能在后台查看。”
