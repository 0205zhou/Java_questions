重写和重载的区别

重写和重载的区别

重写(Override)与重载(Overload)的区别

联想记忆法

记忆口诀/联想

口诀:"重写靠继承,签名要相同,权限不能小,异常不能大;重载看本类,同名不同参,返回类型不管,编译期定夺"

拆成两句:

  • 重写(Override):"抄父亲的卷子"——子类把父类的方法重新实现一遍,方法签名(名字+参数)必须一致,权限只能放大不能缩小,抛的异常只能变少不能变多
  • 重载(Overload):"同名不同脸"——同一个类里,方法名相同但参数列表不同(个数/类型/顺序),与返回类型无关,编译器根据实参挑选

记忆原理

用"抄卷子 vs 换脸"两个画面区分:重写是"继承中的覆盖"(纵向,父子之间),重载是"类内的多胞胎"(横向,同类之间)。一个"上下"关系,一个"左右"关系——先定这个方向,再记规则细节。关键词锚点:"重写 = 父子 + 签名同 + 权限大 + 异常小";"重载 = 同类 + 名同 + 参不同 + 返回无关"。四个锚点各四个字,容易成串记忆。

关联知识

  • 与多态关联:重写是运行时多态(动态分派,invokevirtual 根据对象实际类型找方法),重载是编译时多态(静态分派,编译期按参数类型决定)
  • 与 @Override 注解关联:注解让编译器帮我们校验"是否真的是重写",写错签名立刻报错
  • 与构造器关联:构造器可以重载(多个构造函数),不能重写(构造器名必须与类名相同,无继承可言)
  • 与 static/final 方法关联:static 方法不参与重写(隐藏),final 方法禁止重写
  • 与泛型关联:泛型方法的重写要格外小心桥方法(Bridge Method)的存在

深度解答

第一层:核心概念

两者是什么

  • 重写(Override):子类中定义与父类方法签名相同的方法,替换父类实现。发生在继承关系中,是实现运行时多态的机制
  • 重载(Overload):同一个类中定义多个同名但参数列表不同的方法,编译期按参数选择。发生在同一个类(或继承链中的类)内
// 重载:同一类中,同名不同参
public class Calculator {
    public int add(int a, int b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }   // 参数个数不同
    public double add(double a, double b) { return a + b; }     // 参数类型不同
}

// 重写:子类替换父类实现
public class Animal {
    public void speak() { System.out.println("动物叫"); }
}
public class Dog extends Animal {
    @Override
    public void speak() { System.out.println("汪汪"); }         // 覆盖父类实现
}

核心区别一句话

重写是"纵向"的——父子类之间重新实现同一签名的方法;重载是"横向"的——同类内同名方法用不同参数区分。重写是运行时行为(多态),重载是编译时行为(选择)。

第二层:底层原理

重写的完整规则(面试高频)

规则 要求 反例
方法签名 方法名 + 参数列表必须完全一致 参数变了就是重载,不是重写
返回类型 相同或子类型(协变返回类型) 返回类型无关的改动不允许
访问权限 不能缩小(父 protected → 子不能 private) 权限放大可以(protected → public)
异常 不能抛出更宽泛的受检异常(只能变少/变同) 父抛 IOException → 子抛 Exception 不行
static/final/private 不能重写(static 是"隐藏",final/private 不允许) 同名 static 方法只是隐藏父类方法 
class Parent {
    protected Number getValue() throws IOException { return 1; }
}
class Child extends Parent {
    @Override
    public Integer getValue() throws FileNotFoundException {  // ✅ 权限放大 + 返回协变 + 异常缩小
        return 2;
    }
}

底层机制:静态分派 vs 动态分派

  • 重载 = 静态分派(Static Dispatch):编译期根据实参的声明类型选择方法,生成 invokevirtual/invokestatic 指令时已确定调用哪个
Calculator c = new Calculator();
c.add(1, 2);        // 编译期就确定调用 add(int,int)
  • 重写 = 动态分派(Dynamic Dispatch):编译期只知道调用点,运行时根据对象的实际类型决定调哪个方法。JVM 通过虚方法表(Virtual Method Table, vtable) 实现:每个类持有一张方法表,子类重写后表中的槽位指向自己的实现
Animal a = new Dog();
a.speak();          // 编译期:Animal.speak;运行期:vtable 查到 Dog.speak → "汪汪"

为什么返回值类型默认不允许改

调用者在编译期根据声明的方法签名确定返回类型。如果允许任意改返回类型,Parent p = new Child(); p.getValue() 到底返回 Number 还是 Integer,编译期无法确定类型安全。协变返回类型(Covariant Return)是个例外:返回类型是父类返回类型的子类型时安全(JVM 用桥方法实现),所以 JDK5+ 允许。

重载选择规则(编译期匹配顺序)

实参匹配按"最精确优先"逐级降级:

void f(int i)        { }
void f(double d)     { }
void f(long l)       { }
f(10);               // 匹配 f(int) —— 最精确

如果找不到精确匹配,依次尝试:类型提升(int→long→float→double) → 装箱(Integer) → 可变参数,同层有多个可匹配则编译报错(歧义)。

void f(Integer i) { }
void f(long l)    { }
f(10);            // 编译报错:装箱(→Integer)和类型提升(→long)同一优先级,歧义!

第三层:实践应用

用 @Override 让编译器把关

public class Dog extends Animal {
    @Override
    public void speak() { ... }      // ✅ 编译器校验:签名一致才算重写

    // @Override
    // public void speek() { ... }   // ❌ 拼写错误:加注解会直接编译报错,及时发现
}

最佳实践:所有重写方法一律加 @Override,这是编译器白送的"签名校验",写错了立刻报错,而不是静默地变成"新方法"。

重载的典型应用场景

// 1. 构造器重载:不同初始化方式
public class User {
    private String name;
    private int age;
    public User() { }
    public User(String name) { this.name = name; }
    public User(String name, int age) { this.name = name; this.age = age; }
}

// 2. 方法重载:不同参数形态的入口
public class FileUtil {
    public static String read(File f) { ... }
    public static String read(String path) { ... }              // 便捷入口
    public static String read(InputStream in) { ... }
}

// 3. JDK 中的重载:Stream.of
Stream.of("a");
Stream.of("a", "b");
Stream.of(new String[]{"a", "b"});     // 同名方法,参数形态不同

重载与重写同时出现:调用谁?

public class A {
    public void test(A a) { System.out.println("A.test(A)"); }
    public void test(B b) { System.out.println("A.test(B)"); }  // 重载
}
public class B extends A {
    @Override
    public void test(A a) { System.out.println("B.test(A)"); }  // 重写
}

A a = new B();
B b = new B();
a.test(b);
// 第一步编译期:实参 b 的声明类型是 B → 选签名 test(B)
// 第二步运行期:对象实际类型是 B → 查找 B 中的 test(B) → 没有 → 继承 A.test(B)
// 结果:"A.test(B)"

规则总结:先按声明类型选签名(重载),再按实际类型找实现(重写)——重载决定"调哪个方法",重写决定"实现是谁"。

第四层:深入思考

追问 1:static 方法能重写吗?

不能。"重写"要求动态分派(运行时按对象类型),而 static 方法属于类,编译期就绑定,父子类中同名 static 方法只是隐藏(Hiding),调用时跟引用类型走,与多态无关:

Animal a = new Dog();
a.staticSpeak();     // 调 Animal 的 staticSpeak(按声明类型)
Dog d = new Dog();
d.staticSpeak();     // 调 Dog 的 staticSpeak

追问 2:private 方法会被重写吗?

不会。private 方法对子类不可见,子类写同名同参方法只是"新方法",不构成重写。所以 private 方法、static 方法、final 方法、构造器四类方法不能被重写。

追问 3:JDK5 为什么允许"协变返回类型"?

因为 JVM 用桥方法(Bridge Method) 兼容:编译器生成一个返回父类型的桥方法,内部转调子类的实际方法,既满足字节码层面的签名校验,又让 Java 层面可以收窄返回类型。这是"语言语法演进但字节码不破坏兼容"的典型设计。

追问 4:重载时方法可以只改返回类型吗?

不可以。只改返回类型、参数相同,不构成重载,编译器报"重复定义"。因为调用方只看参数选方法,只看返回类型无法区分该调哪个。

回答思路

答题逻辑框架(约 1.5 分钟)

  1. 一句话总起:重写是父子类间的"覆盖",重载是同类内的"多胞胎"
  2. 逐项对比(表格化):位置关系、方法签名、返回类型、权限/异常、绑定时机
  3. 讲绑定机制:重载 = 编译期静态分派;重写 = 运行期动态分派(vtable)
  4. 给实践建议:重写必加 @Override;重载别只改返回类型
  5. 收尾升华:重写是运行时多态的实现,重载是编译期便利设计

重点得分点

  • 准确说出重写四大规则:签名同、权限不小、异常不大、返回协变
  • 准确说出绑定时机:编译期(重载) vs 运行期(重写)
  • 说出 static/final/private/构造器不能重写
  • 用代码演示 "先按声明类型选重载,再按实际类型找重写"(资深加分点)

常见误区

  • ❌ 说"重写可以改参数列表"——改参数就是重载,不是重写
  • ❌ 说"返回类型和重载无关,所以可以随便改"——只改返回类型不是重载,是重复定义
  • ❌ 以为 static 方法能重写——只是隐藏,按声明类型调用
  • ❌ 忘了权限缩小/异常扩大是重写的编译错误——这是最常见的两个雷区

过渡话术

  • 开头定调:"这两个词天天听到,但一个靠继承、一个靠签名,先定方向再谈规则……"
  • 讲绑定:"重载的选择发生在编译期,而重写的派发发生在运行期,这正是多态的实现机制——JVM 靠虚方法表在运行时找到正确实现……"
  • 收尾:"记住实践口诀:重写必须加 @Override 让编译器把关,重载永远别只改返回类型。"
