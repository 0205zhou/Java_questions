线程的状态有哪些

线程 状态 生命周期

线程的状态有哪些

联想记忆法

记忆口诀/联想

口诀:"新生(New)就绪(Runnable)拦(Blocked)等(Waiting)限时(Timed_Waiting)终(Terminated)——六态一条链,就绪含运行"

把线程生命周期想成一个人的一天:

  • New:刚出生(对象创建了,还没 start)
  • Runnable:排队等电梯 + 坐电梯中(Java 把"就绪"和"运行"合并,OS 态才分开)
  • Blocked:被保安拦在门外(等 synchronized 锁)
  • Waiting:在候车室干等(等 notify/wait、join,不限时)
  • Timed_Waiting:限时等待(sleep、wait(1000)、join(1000))
  • Terminated:下班注销

注意:RUNNABLE 包含"运行中"和"可运行"两个 OS 状态,是 Java 六态里最容易误解的一个。

记忆原理

用"人的一天"串联六个状态,关键锚点是三个等待的区分:Blocked = 抢锁被拦(被动)、Waiting = 主动无限期等、Timed_Waiting = 主动限时等。记住"锁、通知、时间"三个关键词分别对应三种等待态,状态转换图就能默写出来。再记一个反直觉点:RUNNABLE ≠ 正在运行。

关联知识

  • 与 synchronized 关联:Blocked 状态专属于 monitor 锁竞争,引出锁升级
  • 与 Object.wait/notify 关联:Waiting 态的进入与唤醒,经典生产者消费者
  • 与 Thread.sleep/join 关联:Timed_Waiting 的常见来源
  • 与线程池关联:池中线程复用,状态一直在 RUNNABLE 和等待态间切换

深度解答

第一层:核心概念

是什么

Java 线程有 6 种状态,定义在 Thread.State 枚举(JDK 1.5 引入):

状态 含义 进入方式 退出方式
NEW 已创建未启动 new Thread() start()
RUNNABLE 可运行(含运行中/就绪) start();等待结束、抢到锁 正常调度/阻塞
BLOCKED 阻塞等 monitor 锁 进入 synchronized 块而锁被占用 抢到锁
WAITING 无限期等待 wait()(无参)、join()(无参)、LockSupport.park() notify/notifyAll、目标线程结束、unpark
TIMED_WAITING 限时等待 sleep(ms)、wait(ms)、join(ms)、LockSupport.parkNanos/parkUntil 时间到、唤醒
TERMINATED 已终止 run() 正常返回或抛出异常 —

第二层:底层原理

状态转换图

      ┌──────────────┐
      │     NEW      │ start()
      └──────┬───────┘
             ▼
      ┌──────────────┐  获得 CPU 调度  ┌────────────┐
      │   RUNNABLE   │ ◄────────────── │  RUNNABLE  │
      │  (ready+run) │                 │  (running) │
      └──┬───┬───┬───┘                 └────────────┘
         │   │   │         （Java 层面合并为一个状态）
   synchronized│   │
    竞争锁失败 │   │  wait/join/park        sleep/wait(ms)/join(ms)
         ▼   │   ▼                        ▼
   ┌────────┐│ ┌────────┐          ┌──────────────┐
   │BLOCKED ││ │WAITING │          │TIMED_WAITING │
   └────────┘│ └────────┘          └──────────────┘
   （拿到锁 → RUNNABLE）（notify → RUNNABLE）（时间到/唤醒 → RUNNABLE）
          （run() 完成或异常 → TERMINATED）

关键辨析

1. RUNNABLE 合并了 OS 的 ready 和 running。 Java 不区分"等待 CPU"和"正在执行",都算 RUNNABLE。所以 Thread.getState() 返回 RUNNABLE 不代表线程真的在跑——它可能只是排队等 CPU。

2. BLOCKED vs WAITING 的本质区别:
- BLOCKED:被动等 monitor 锁(synchronized 的临界区进不去),靠别的线程释放锁才能继续,且不受 interrupt 影响(interrupt 不会把 BLOCKED 变回 RUNNABLE)
- WAITING/TIMED_WAITING:通常是主动调用 wait/join/sleep,靠 notify/时间到/目标线程结束来唤醒

3. interrupt 与状态的关系:
- WAITING/TIMED_WAITING 中收到 interrupt → 抛 InterruptedException → 回到 RUNNABLE
- BLOCKED 中收到 interrupt → 不生效,仍处于 BLOCKED 直到拿到锁

4. 为什么 NEW 调 start 而不是 run? start() 通过 native 方法 start0() 创建真正的 OS 线程并进入 RUNNABLE;直接调 run() 只是普通方法调用,不新建线程,状态停在原线程上。

第三层:实践应用

public static void main(String[] args) throws Exception {
    Thread t = new Thread(() -> {
        synchronized (LOCK) {
            try { Thread.sleep(100); } catch (InterruptedException e) {}
        }
    });
    System.out.println(t.getState());      // NEW
    t.start();
    Thread.sleep(10);
    System.out.println(t.getState());      // RUNNABLE 或 BLOCKED/TIMED_WAITING
    t.join();
    System.out.println(t.getState());      // TERMINATED
}
  • 排查工具:jstack <pid> 能看到线程栈和状态;WAITING/BLOCKED 大量堆积是死锁、锁竞争、线程泄漏的排查入口
  • 死锁特征:两个线程互持对方需要的锁,都处于 BLOCKED,jstack 会直接打印 "Found one Java-level deadlock"
  • 避免阻塞:能用限时等待(TIMED_WAITING)就不用无限等待(WAITING),wait(timeout)、lock.tryLock(timeout) 能防止永久挂起

第四层:深入思考

追问 1:线程池里的线程是什么状态?
线程池工作线程循环从队列取任务:取不到任务时 workQueue.take() 进入 WAITING;取到任务执行时 RUNNABLE;任务执行中若再调 sleep/wait 则相应进入 TIMED_WAITING/WAITING。线程池不会反复创建销毁线程,状态在 RUNNABLE 与等待态间循环。

追问 2:wait 和 sleep 有什么区别?
wait 释放锁、必须有锁才能调用、由 notify 唤醒;sleep 不释放锁、无锁要求、时间到自动醒。状态上:wait 进 WAITING(无参)或 TIMED_WAITING(有参),sleep 进 TIMED_WAITING。

追问 3:yield() 是什么状态?
yield 只是从 running 让出 CPU 回到 ready(仍属 RUNNABLE),是"谦让"提示,不保证生效,且 Java 层状态不变。

常见误区

  • ❌ "线程有 5 个状态(混淆 OS 5 态模型)"——Java 是 6 态枚举
  • ❌ "RUNNABLE 就是正在运行"——含就绪
  • ❌ "interrupt 能打断 BLOCKED"——不能
  • ❌ "run() 能启动线程"——只有 start() 才创建线程进入 RUNNABLE
