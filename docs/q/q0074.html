MyBatis里#和$区别？

联想记忆法

记忆口诀/联想

口诀：# 走预编译，$ 走字符串拼接；值用 #，名用 $.

  • #{}：先占位，再绑定参数，安全。
  • ${}：直接把文本拼进 SQL，灵活但危险。
  • 值用 #，名用 $：参数值优先 #{}，列名、表名这类标识符才考虑 ${}。

记忆原理

这道题核心不是语法，而是“安全和灵活的取舍”。
把 # 记成“预编译参数”，把 $ 记成“文本替换”，后面 SQL 注入、执行计划复用、动态列名这些点就自然串起来了。

关联知识

  • 会关联到 PreparedStatement：#{} 本质上是 ? 占位符。
  • 会关联到 SQL 注入：${} 直接拼接有风险。
  • 会关联到 执行计划缓存：#{} 更容易复用。
  • 会关联到 动态排序：ORDER BY ${column} 是典型场景。

深度解答

1. 核心概念：#{} 是参数绑定，${} 是字符串替换

MyBatis 里的 #{} 和 ${} 经常一起出现，但它们完全不是一回事。

#{} 的效果更像：

select * from user where id = ?

MyBatis 会把参数交给 PreparedStatement 绑定，值不会直接拼进 SQL。

${} 的效果更像：

select * from user where id = 1

它会在 SQL 解析前直接替换成文本。

2. 底层原理：为什么 #{} 更安全

#{} 走的是预编译流程：

  1. MyBatis 解析 SQL
  2. 把 #{} 转成 ?
  3. 通过 PreparedStatement 绑定参数
  4. JDBC 驱动负责转义和执行

这样做的好处：

  • 防 SQL 注入
  • 能复用执行计划
  • 类型转换更规范

而 ${} 只是纯文本替换，数据库会把它当成 SQL 片段的一部分。
如果参数来自用户输入，就可能被拼出恶意 SQL。

3. 实践应用：什么时候用谁

正确示例：值用 #{}

select * from user where name = #{name}

谨慎示例：列名、排序字段可能用 ${}

select * from user order by ${column}

但这里必须先做白名单校验，比如只允许 id、create_time 这类固定字段，否则风险很大。

4. 深入思考：为什么 MyBatis 还要保留 ${}

如果所有地方都只能 #{}，就没法动态拼接表名、列名、排序方向、分库分表路由等 SQL 结构信息。
所以 ${} 的存在是为了处理“SQL 结构本身需要变化”的场景，而不是拿来放普通参数值。

简单记：

  • 值：用 #{}
  • 结构：谨慎用 ${}

回答思路

答题逻辑框架

  1. 先说 #{} 是预编译参数绑定，$ 是字符串替换。
  2. 再说 #{} 通过 PreparedStatement 更安全。
  3. 然后说 ${} 适合列名、表名等结构性字段。
  4. 最后强调 ${} 要做白名单，避免注入。

重点得分点

  • 能说出 #{} 对应 ? 占位符。
  • 能说明 ${} 会直接拼接 SQL。
  • 能讲清 SQL 注入风险。
  • 能举出 ORDER BY ${column} 这类例子。

常见误区

  • 误区 1：$ 也会自动转义。
    正解：不会，直接文本替换。

  • 误区 2：# 和 $ 只是写法不同。
    正解：本质是预编译和拼接的区别。

  • 误区 3：${} 不能用。
    正解：能用，但只适合少数结构性字段，并且要白名单。

面试话术

“MyBatis 里 #{} 是参数绑定，会生成 ?，走 PreparedStatement，更安全也更利于执行计划复用；${} 是纯字符串替换，适合动态表名、列名、排序字段这类 SQL 结构，但有 SQL 注入风险，所以普通参数值尽量用 #{}。”
