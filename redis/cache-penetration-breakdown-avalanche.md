# 缓存穿透、缓存击穿、缓存雪崩怎么解决

> 类型:Redis / 缓存
> 提问频率:⭐⭐⭐⭐⭐(必考题)

---

## S (Situation) — 背景

高并发系统中,Redis 缓存是保护数据库的第一道防线:

```
请求 → 查 Redis(命中 → 直接返回)
         ↓ 未命中
      查数据库(DB)
         ↓
      回写缓存 → 返回
```

当缓存出现异常场景时,大量请求会直接穿透到数据库,把数据库打垮。经典问题有三个:**缓存穿透、缓存击穿、缓存雪崩**。

## T (Task) — 要解决的问题

| 问题 | 一句话描述 | 核心特征 |
|---|---|---|
| **缓存穿透** | 查「缓存和 DB 都不存在」的数据 | 数据不存在,一直打 DB |
| **缓存击穿** | 某个热点 key 过期的瞬间,并发打 DB | 一个 key,过期瞬间,高并发 |
| **缓存雪崩** | 大量 key 同时过期,或 Redis 宕机 | 多个 key 或整个缓存不可用 |

## A (Action) — 三种问题的解决方案

### 一、缓存穿透(数据不存在,空数据绕过缓存)

**原因**:查询的数据在缓存和数据库中都不存在,缓存永远没有该 key,每次请求都直达数据库。

**解决方案**:

1. **缓存空值**
   - 查 DB 为空时,也写入缓存(值为 null,过期时间设短,如 5 分钟)
   - 防止恶意攻击用不存在的 id 反复打 DB
2. **布隆过滤器 (Bloom Filter)**
   - 请求先进布隆过滤器,判断 key 是否「可能存在」
   - 不存在 → 直接拒绝,不查缓存和 DB;存在 → 放行(允许小概率误判)
   - 能挡住绝大多数非法 key
3. **参数校验**
   - 对 id、页码等参数做合法性校验(如 id 必须为正数、不能越界),非法直接返回

### 二、缓存击穿(热点 key 过期瞬间)

**原因**:某个**热点 key**(如热门商品、热点新闻)过期的瞬间,大量并发请求同时发现缓存未命中,全部打到数据库。

**解决方案**:

1. **互斥锁 (Mutex)**
   - key 失效时,只让**一个线程**去查 DB 重建缓存,其他线程自旋等待或返回降级数据
   - 用 Redis SETNX 实现分布式锁;缺点:极端情况下有等待延迟
2. **逻辑过期(缓存中带逻辑过期时间)**
   - 存数据时同时存一个逻辑过期时间,查询时发现「逻辑过期」→ 直接返回**旧数据**,后台异步线程去更新缓存
   - 读写不阻塞,吞吐最高;缺点:短暂存在脏数据
3. **热点 key 永不过期**
   - 物理上不设置过期时间,由后台定时任务主动刷新

### 三、缓存雪崩(大量 key 同时过期 / Redis 宕机)

**原因**:大量 key 设置了相同的过期时间,同一时刻集体过期;或 Redis 服务宕机,所有请求直达数据库。

**解决方案**:

1. **过期时间加随机值**
   - 每个 key 的过期时间 = 基础时间 + 随机数(如 1~5 分钟)
   - 避免 key 在同一时刻集体过期
2. **多级缓存**
   - 本地缓存(Caffeine / Guava)+ Redis
   - Redis 挂了,本地缓存还能兜底
3. **高可用保障**
   - Redis 主从 + 哨兵 / 集群,保证 Redis 本身不宕机
4. **限流降级**
   - 用 Sentinel / Hystrix 对数据库访问限流、熔断降级,保护 DB
5. **数据预热**
   - 上线前 / 高峰期前,把热点数据提前加载进缓存

## R (Result) — 效果

| 方案 | 防穿透 | 防击穿 | 防雪崩 |
|---|---|---|---|
| 缓存空值 / 布隆过滤器 | ✅ | — | — |
| 互斥锁 / 逻辑过期 | — | ✅ | — |
| 过期时间随机化 / 多级缓存 / 高可用 / 限流 | — | — | ✅ |

三层防线各管一段,从「挡无效请求」到「控制热点重建」再到「避免整体失效」,最终保护数据库不被压垮,保证系统高可用。

---

## 💡 追问点速背

1. **穿透和击穿的区别?** → 穿透是数据不存在;击穿是热点 key 过期瞬间
2. **击穿和雪崩的区别?** → 击穿是 1 个 key 瞬间失效;雪崩是大量 key 同时失效或 Redis 宕机
3. **布隆过滤器的缺点?** → 有误判率(会把不存在的判为存在)、不能删除元素(除非用计数布隆)
4. **互斥锁的缺点?** → 大量线程等待,吞吐下降,极端情况下可能死锁(要设置锁超时)
5. **逻辑过期的缺点?** → 有短暂脏读,且要额外保证异步更新的一致性
6. **数据库怎么二次保护?** → 连接池限流 + 数据库读写分离 + 降级返回兜底数据
